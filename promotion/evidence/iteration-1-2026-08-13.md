The **first** `npm test` in the fresh clone reported `1 failed | 148 passed`.
That run took 45 s against a normal 18 s, and the failure did not reproduce in
the five runs after it — two in-tree and three more in the fresh clone, all
`149 passed (149)`. The failing test name was not captured before the output
scrolled, so it cannot be named. The four tests added by this iteration read
committed files and parse JSON with no timing or ordering dependency; the suite
does contain gate and runner tests that assert on elapsed milliseconds. Filed as
an unidentified pre-existing flake under machine contention. Not fixed, not
dismissed.

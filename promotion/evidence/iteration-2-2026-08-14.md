## Two failures of the new tooling, kept because they are the interesting part

Both were in the probe, not the page, and both looked exactly like page defects.

1. **`spawnSync` starved the server it was auditing.** `scripts/web-audit.mjs`
   serves the page from the same Node process that launches Lighthouse. With
   `spawnSync`, the event loop is blocked for the whole audit, so the page never
   answers a request. Lighthouse spent six minutes in `PROTOCOL_TIMEOUT` and
   concluded *"The page did not paint any content … (NO_FCP)"* — a sentence that
   reads like a broken page. Fixed by using async `spawn` and awaiting it; the
   same audit then finished in 15.6 s with performance 1.00. The failing logs
   were overwritten by the successful re-run — only the passing
   `web-audit/lighthouse.log` is committed — so the failure is described here
   rather than cited, which is the honest form.
2. **`@axe-core/cli --save` joins its argument onto the current directory.** An
   absolute path became `<cwd>\C:\Users\…`, and the run ended `Unable to save
   file!` *after* printing `0 violations found!` — a clean audit with no
   artifact, which under this gate is worth nothing. Fixed by passing a relative
   path.

A third dead end is recorded so nobody re-walks it: the quoting of
`--chrome-flags` and Windows backslashes in `--output-path` were both suspected
first and were both innocent.
